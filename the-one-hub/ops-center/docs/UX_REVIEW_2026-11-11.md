## 4. Contribute page (capture)

* Answer panel first, sticky beside the question list; no scrolling to reach it.
* Click a question: GET /api/gaps/{id}/brief, built only then (not preloaded), cached per gap when a model wrote it.
  * Evidence by code: register row, exposure, variances that cite the gap, unattributed blocks it blocks, prime-contract transactions it names (count, sum, 5 largest, link to the detail table).
  * Summary by the agent model chain: what it is, what we have, what is needed, how you can help. A code-built summary when no model answers, and the panel says which.
  * Limitation: only G24 names a contract the transaction matcher recognises, so most briefs show no transactions.
* Document upload: up to 3 files, 10 MB each, typed allowlist; sent as base64 JSON (no multipart dependency).
* Storage: written to AIRCARRIER_CAPTURE_VOLUME (/Volumes/...) as capture.json plus files when set. Not set today, so the reply says "not stored". The app SP needs WRITE VOLUME on that volume.
* Engagement: plain stats (answerable / need access / closed), filter by text and type, "answerable now" chip, a "why your answer matters" card, honest status messages.

Next ideas, not built: show the contributor what their answer changed once a gap closes; a monthly "questions in your office" e-mail to named executors; a leaderboard only if the sponsor wants attribution made visible.
